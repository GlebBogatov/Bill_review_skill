# Bill-review — сбор чеков из Gmail в PDF-архив

Личный workflow сбора чеков/квитанций из Gmail и рендера их в PDF. Один и тот же
процесс работает как ежедневная cron-задача и как интерактивная сессия.

## Когда использовать

- «Собери чеки за месяц», «сохрани квитанции», «заархивируй чеки из почты».
- Плановый запуск (cron): ежедневно собрать новые фискальные документы.
- Разовая обработка новых писем от известных ОФД-отправителей.
- Поиск новых источников чеков (незнакомые отправители).

## Что делает (обзор)

1. Считает окно поиска: **месяц назад** от сегодня.
2. Делает **один** Gmail-запрос по всем известным отправителям (см.
   `references/providers.md`).
3. Сверяет найденные письма с уже сохранёнными чеками **по ФПД из имён файлов**
   (идемпотентность — главное).
4. Для реально новых чеков извлекает поля, рендерит PDF в
   `<архив>/<год>/<магазин>/Чек_YYYY-MM-DD_<ID>.pdf`.
5. Пишет одну строку в журнал и краткий отчёт.

## Конфигурация

Перед первым запуском заполни `references/configuration.md`: корень архива,
домашняя папка, путь к Python, аккаунт Gmail (к которому подключён Gmail MCP),
временная папка. Дальше по тексту эти значения обозначены как `<АРХИВ>`,
`<HOME>`, `<PYTHON>`, `<TEMP>`.

Требуется: Gmail MCP (read-only достаточно), headless Google Chrome, Python 3,
PowerShell. `jq` не обязателен — JSON парси Python'ом.

## Рабочий процесс

### 1. Окно поиска

Окно — **месяц**: `after:YYYY/M/D`, где дата = сегодня минус 31 день. Перекрытие
с предыдущими запусками намеренное — от дублей защищает идемпотентность (шаг 3),
а не узкое окно.

### 2. Один Gmail-запрос

Собери всех известных отправителей в один запрос (готовый шаблон и таблица
провайдеров — в `references/providers.md`). НЕ читай письма по одному. Если
результат пуст — выход, одна строка в журнал.

### 3. Идемпотентность (главное)

Имя файла: `Чек_YYYY-MM-DD_<ID>.pdf` (кириллическое «Чек»), путь —
`<АРХИВ>\<год>\<магазин>\`.

- Российские ОФД-чеки: `<ID>` = **ФПД** (он же ФП, 9–10 цифр).
- Иностранные сервисы (Anthropic и др.): `<ID>` = номер чека/инвойса из письма.

**Источник истины — файлы на диске, не журнал.** Рабочий приём (быстро и
надёжно):

1. До обработки собери множество уже сохранённых ID за текущий год:
   `python <PYTHON> scripts/collect_saved_ids.py "<АРХИВ>\<год>"`.
2. Сверяй найденные письма с этим множеством. Тела писем (шаг 4) запрашивай
   **только для тех, кого нет в множестве** — это резко сокращает работу.
3. **Перед рендером** ещё раз проверь существование целевого файла — если есть,
   пропусти.
4. **После рендера** проверь, что файл создан и его размер **> 4 КБ**. Если
   меньше — удали и считай чек необработанным (попадёт в следующий запуск).

Приём сверки по (магазин + дата + количество писем) тоже валиден, когда ФПД в
теле: если у отправителя на эту дату уже лежит ровно столько файлов, сколько
писем в нити, — всё сохранено, тело можно не запрашивать. ⚠ У `noreply@ofd.ru`
одна нить = несколько разных чеков — считай сообщения по отдельности.

### 4. Извлечение полей

Источник — `get_thread(threadId, FULL_CONTENT)` → `htmlBody` (у Anthropic —
`plaintextBody`). Теги при необходимости снимай regex `<[^>]+>`.

- **Дата** — поле `date` сообщения (ISO, UTC) → `YYYY-MM-DD` по МСК (UTC+3). У
  Магнита/Такскома дублируется в теле.
- **ФПД/ФП** — `(?:ФПД|ФП)[:\s№]+(\d{6,10})` или `fpd=(\d+)` в URL.
- **ФН** — `(?:ФН|FN|№\s*ФН)[:\s№]+(\d{16})`.
- **ФД** — `(?:ФД|FD|№\s*ФД)[:\s№]+(\d+)`.
- **Магазин/ИНН** — имя организации до `ИНН <digits>` (для выбора папки).

**Крупные тела.** `htmlBody` возвращается всегда. Магнит (~100–130 КБ) может
превысить лимит токенов MCP и авто-сохраниться в файл
`…\tool-results\…get_thread…txt`. Тогда извлекай `htmlBody` из файла скриптом
`scripts/extract_html_body.py`, **не втягивая в контекст**. Сверка из шага 3
сокращает такие запросы до реально новых чеков.

### 5. Рендер PDF

**Только headless Google Chrome** (`chrome.exe`, не Edge, не Claude in Chrome).
Детали по каждому провайдеру — в `references/providers.md`. Три случая:

- **Ссылочные** (Яндекс.Маркет, Такском, Яндекс.Доставка): печатай URL напрямую.
- **OFD.ru** — исключение, Chrome НЕ нужен: скачивай готовый фискальный PDF
  `Invoke-WebRequest` по
  `https://ofd.ru/Document/RenderDoc?RawId=<GUID>&format=pdf`.
- **HTML-тело** (Магнит, Билайн, ЛитРес, 1-ОФД; Anthropic — обёртка plaintext):
  сохрани `htmlBody` в `<TEMP>\receipt.html` и печатай `file:///…`.

Рендер — через `scripts/render_receipt.ps1` (PowerShell `Start-Process -Wait`).
Форма bash (`&` + `2>$null`) файл НЕ создаёт надёжно — не используй её.

⚠ **Подводный камень (проверено).** Некоторые окружения имеют path-guard,
блокирующий команду, где в одном тексте есть `Remove-Item` и путь
`"C:\Program..."` (путь к chrome.exe) — он принимает это за удаление системного
пути. Поэтому **рендер и удаление недоразмерных файлов держи в разных командах**:
сначала отрендерь всё без логики удаления, затем отдельной командой проверь
размеры и при необходимости удали.

Chrome может писать в stderr `GCM DEPRECATED_ENDPOINT` / `PHONE_REGISTRATION_ERROR`
/ `TensorFlow Lite` — безвредный шум, не ошибка.

### 6. Незнакомые отправители и еженедельный discovery

Если в теле письма есть «Кассовый чек»/«КАССОВЫЙ ЧЕК» и парсится ФПД —
автоматически создай папку по магазину (имя организации до ИНН; кириллица +
подчёркивание, напр. `Имя_Организации`) и сохрани чек. Отметь факт
в отчёте.

Раз в неделю делай расширенный запрос для поиска новых источников:
`("Кассовый чек" OR "КАССОВЫЙ ЧЕК") after:YYYY/M/D` с исключением известных
отправителей (`-from:...`), и заводи новых в `references/providers.md`.

### 7. Журнал

В начало журнала (`<HOME>\...\memory\sessions_bill_review.md` или иной путь из
конфигурации) — **одна строка на запуск**:

```
YYYY-MM-DD | after:YYYY/M/D | saved: N (список через ;) | skipped: M (отправитель/дата — причина; ...)
```

или `YYYY-MM-DD | after:YYYY/M/D | ничего`. **Пропуск с причиной обязателен** —
чтобы видеть деградации (Gmail MCP без body, Chrome crash и т.п.). Журнал — для
аудита; источник истины об «уже обработано» — файлы (шаг 3).

### 8. Отчёт

Одна строка на сохранённый чек + строка на каждый пропуск с причиной + итог.
Если ничего нового — «Нет новых чеков с <дата>».

## Материалы скилла

- `references/providers.md` — таблица известных отправителей, формулы URL,
  извлечение полей и способ рендера для каждого. **Читай перед составлением
  Gmail-запроса и перед рендером.**
- `references/configuration.md` — пользовательские настройки (пути, аккаунт,
  соответствия ИНН → папка). **Заполни перед первым запуском.**
- `scripts/collect_saved_ids.py` — множество уже сохранённых ID из архива
  (идемпотентность).
- `scripts/extract_html_body.py` — извлечение `htmlBody`/`plaintextBody` из
  сохранённого JSON-результата `get_thread`.
- `scripts/render_receipt.ps1` — рендер URL или HTML-файла в PDF headless
  Chrome с проверкой размера.

## Быстрые факты окружения (Windows-референс)

- Домашняя папка может быть кириллической (`C:\Users\<Имя>\...`);
  транслитерированный путь (`C:\Users\<Name>\...`) может не существовать — бери
  путь из конфигурации.
- Python вызывай полным путём (`<PYTHON>`); голый `python`/`python3` в bash иногда
  резолвится в заглушку WindowsApps и падает (exit 49).
- `jq` может отсутствовать — парси JSON Python'ом.
- Hook-ошибки Claude Code (отсутствующие pre/post-скрипты) — игнорируй.
